Warden

Enforcing What AI Agents Can Do Below the Shell
Arkar Myat (Computer Science), May Aung (Computer Systems Technology), Professor Lawrence Ryan (Data Science)
[City Tech logo]
01

Abstract

LLM agents increasingly execute shell commands, but prompts and userspace command filters reason about text while damage occurs through system calls. Warden is a small x86-64 research kernel that labels every agent process with a session, capability set, and writable filesystem scope; labels persist across fork and exec, files remember the agent that wrote them, and a fail-closed dispatch table checks every system call. Against a worst-case agent, an escape suite of 12 attacks run through the agent daemon under four configurations, kernel enforcement blocks 12/12, a careful userspace deny-list 4/12, and prompt rules alone 1/12. In a preliminary run of 32 model-driven tasks, enforcement cost no task success.

02

Introduction & Background

Coding and operations agents act through tools such as run_shell(command), which can create, modify, execute or delete files with the authority of the user who started the agent. The AgentDojo benchmark contains 629 security test cases across 97 realistic tasks [1].

Most systems rely on prompt rules or a userspace wrapper that rejects suspicious command strings. Both act before the shell interprets the command. A shell can build the same action through quoting, variables, cd, path traversal, scripts or child processes.

A filter looking for /bin misses:
$ cd /; rm b''in/ls
kernel receives → unlink("/bin/ls")

Warden makes the decision in the kernel. At that point the kernel knows the calling process, the requested system call and the normalized path, no matter how the command was typed.

Research questions
  1. Security. Which escape techniques are blocked by prompt rules, a userspace deny-list, kernel enforcement, and both combined?
  2. Utility. With a real model, what does enforcement cost in task success, and how often does it turn an executed harm into a refused one?
  3. Overhead. What does the capability check cost per ordinary and path-based system call?
03

Methodology

  1. The host opens a session naming the configuration (A–D) and profile; the model proposes one run_shell call per step via an OpenAI-compatible API.
  2. The bridge forwards the command over a Unix socket to QEMU's COM2; /dev/agent delivers it to agentd.
  3. agentd forks. The child redirects output to a pipe, calls mark_agent(session, caps, scope, max_procs) with the profile's values, and only then runs /bin/sh -c.
  4. The label is inherited across fork, kept across exec, and can only narrow. Every syscall passes one dispatch table; paths are checked after normalization.
  5. The parent streams output back in framed OUTPUT messages, ending with a RESULT carrying the exit code. agentd never executes agent input itself.

05

Discussion

After a child process is labeled, writing the same command a different way does not change what it may do. The deny-list catches the attacks it can read, but misses harm one step removed from the line: a nested shell, a script, a program a human runs later. Seven of the twelve attacks never appear in command text at all, and only the kernel blocks them.

agentd keeps its human label, so the trusted code stays small. It labels only the forked child before exec. If labeling fails, the child exits with status 126.

Limitations. We wrote the escape suite ourselves; the deny-list is one point in a family of filters. A model that behaves leaves nothing for any defence to stop, so the model-driven comparison needs tasks drawn from published benchmarks and a weaker second model. The kernel has no network, symbolic links or kernel-managed working directory.

06

Conclusion & Future Work

An agent's permissions can follow its processes across fork and exec and be checked at one kernel entry point. The kernel does not need to parse command text.

  • Run the full 20-task pilot, with injection cases adapted from AgentDojo and InjecAgent.
  • Measure per-syscall overhead of the capability check.
  • Map the design onto Linux: cgroups, Landlock, seccomp, and a BPF-LSM for file labels.
